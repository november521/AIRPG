# NPC AI 输入 API 工程预览

## 如何试玩

1. 启动游戏，在开始界面选择“设置”。
2. 输入 Chat Completions 兼容服务的完整 HTTPS 地址、服务商提供的模型 ID 与 API Key，选择“连接”。
3. 返回并进入庄园原型，靠近标有“身份待确认”的预览 NPC，按 F 打开对话。
4. 在输入框发送文字。完整响应通过结构、知识和动作校验后才显示；若模型选择允许的移动动作，NPC 会面向玩家、停留或走向本场景白名单锚点。
5. 回到设置选择“断开”，可立即清除本次运行中的配置与凭据。

“已配置”只表示输入通过本地校验，不表示服务端已联网认证。首次对话才会产生请求；错误会以稳定错误状态显示，
不会用伪造台词兜底。API Key 提交后从界面清空；它保存在**项目之外的本机配置**里
（`user://ai_credentials.json`，Windows 上是 `%APPDATA%\Godot\app_userdata\AIRPG\`），下次启动自动加载，
设置面板的“断开”会删除该文件。密钥不会进入 `res://`、存档、日志、诊断或导出包；详见
[ADR 0012](adr/0012-local-api-key-storage.md)。文件是明文，只适合个人原型：分发前必须改为服务端转发，
撤销方式是删除本机文件或在服务商侧轮换 Key。

## 当前边界

- 兼容目标是 OpenAI 风格的 `/chat/completions` JSON + SSE 接口；已实现适配器以 DeepSeek 兼容格式为基线。
- 两个 NPC 现已绑定用户交付的角色卡（艾米利亚、玛丽）与分层世界书，见 [npc-characters.md](npc-characters.md)
  与 [ADR 0011](adr/0011-npc-character-cards-and-worldbook.md)；出生点与锚点仍是场景坐标，不是剧情事实。
- 模型不能提供坐标或直接修改场景/剧情，只能提出一个白名单语义动作。
- 原始流不会进入 UI；当前体验是“整条缓存、完整校验、再渐进显示”。
- 本工作包只做离线自动化验证，未使用真实 Key、未向外部 API 发请求，也未验证具体供应商的额度、地区、模型可用性或返回差异。

实现和安全取舍见 [ADR 0009](adr/0009-direct-input-npc-ai.md)。
