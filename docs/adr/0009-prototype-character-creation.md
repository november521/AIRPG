# ADR 0009：演示车卡与确认锁定

状态：已实现演示版。日期：2026-10-03。

## 背景与决定

用户确认：玩家在进入庄园前自行分配数值。六项属性初始均为 50，共 60 点，单项 30–80；察觉、洞察、交涉三项演示技能共 6 点，单项 0–3。姓名和职业必填，背景可选。确认时两类点数必须全部分配；确认后本次会话只读。

这些点数是演示规则，不是完整故事的职业技能表或正式检定公式。当前内容包虽然使用 d20/DC 12/16，但属性原值到修正值的换算尚未确定，因此车卡数值未接入检定结算。

## 实现边界

- `domain/character/creation_rules.gd` 定义演示预算、字段集合和完整候选校验；`creation_state.gd` 做 revision 检查、深拷贝与原子提交。
- `application/character/character_creation_service.gd` 提供只读快照和编辑用例。失败不推进 revision，不修改状态；确认后拒绝继续编辑。
- `presentation/character/creation_view.gd` 只调用应用用例，输入与步进共用同一状态源；超界和超支后回填上一次合法值。
- `bootstrap/main.gd` 在故事档案的庄园原型入口后创建本次会话车卡；确认后进入庄园。庄园内手记从已确认快照展示数值。

## 消费者、兼容与迁移

消费者为车卡页、庄园启动路由、`CharacterService` 的人物视图及手记人物页。旧的物品/生命/理智 `CharacterState` v1 没有改动；原型的测试夹具仍可不经车卡直接实例化庄园。旧版 v1 明确是内存原型状态，本工程尚无写盘角色存档，故没有旧档迁移可执行，也不声称兼容真实旧档。

新增用例仅保存于当前运行会话内存。返回故事档案后重新进入会生成新车卡；退出游戏后数据消失。正式存档、职业范围、推荐分配、随机生成、数值到 d20 修正的公式属于后续独立决策。

## 验证夹具

`game/tests/manor/creation_tests.gd` 覆盖预算、上下限、未知字段、深拷贝、过期 revision、失败回滚、确认锁定、输入回填和重置。故事档案集成测试覆盖“进入车卡 → 未确认阻止进场 → 确认后数值同步到庄园”。
