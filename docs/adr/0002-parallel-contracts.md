# ADR 0002：并行开发的最小稳定接缝

日期：2026-09-26。状态：已采用。

## 背景

工程骨架完成后，探索、对话 UI 和模型传输需要由不同负责人并行实现。若三个分支同时修改启动装配、
SessionService、ModelProvider 或测试总入口，会把并行开发变成高冲突串行合并。AI 原始分片若直接进入 UI，
还会绕过知识与事实验证边界。

## 决策

1. 在 `application/contracts` 冻结三个很小的 v1 接缝：探索意图、对话展示事件和模型传输信封/错误码。
2. 探索命令只表达意图，不携带检定结果或通用状态补丁。
3. 对话 UI 只接受明确标记的已验证回复。切片第一阶段采用整条缓存、完整验证后再渐进播放。
4. 模型传输只处理请求生命周期、原始数据和稳定错误；知识选择、语义裁决、规则和状态提交不属于适配器。
5. 测试替身位于 `tests/doubles`，可用于功能开发和违规生命周期对抗夹具，但不得进入生产装配。
6. 测试套件文件由各工作包独占；聚合入口只在集成阶段由单一负责人修改。

## 代价与限制

完整验证后播放不会真实逐 token 降低首字等待时间，但在首个切片中优先保证未经验证文本不泄漏。
未来若采用可独立验证的分段协议，需要新版本契约、事实边界测试和 UI 消费者同步升级。
当前接缝没有定义正式 NPC 知识、完整模型响应、检定公式或存档格式，不能据此声称这些能力已经完成。

## 复审触发条件

F1/B1 冻结知识和响应 DTO；产品要求真实低延迟分段发布；第二家模型供应商接入；探索意图需要触屏或手柄
特有语义；测试套件数量使单一聚合入口成为持续瓶颈。
