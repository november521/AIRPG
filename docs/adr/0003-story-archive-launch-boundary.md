# ADR 0003：故事档案与故事启动边界

日期：2026-09-28。范围：用户本轮故事选择界面需求，不定义后续玩法。

## 决策

- 故事档案元数据使用独立的 `data/stories/catalog.json` v1；不是正式可游玩内容包。
- `StoryCatalog.validate` 在进入应用层前拒绝未知字段/版本、重复 ID、非法类型和
  缺失本地化；校验整个目录后深拷贝，不部分接收。沿用已有 Schema 子集，不放宽检查。
- `StoryArchiveService` 只提供故事列表快照和 `request_start(id)`，校验 ID 后委托
  注入的 `StoryLauncher.start_story(id) -> Result`。UI 不持有状态、网络或文件句柄。
- 启动端口成功表示后续应用流程已接受并负责接管页面；失败必须无状态副作用。
  当前正式装配使用端口的明确 `STORY_START_UNAVAILABLE` 返回，绝不接测试替身、
  开发灰盒、AI 或虚假游戏流程。UI 淡出后调用，失败淡入恢复并显示固定本地化提示。
- 美术通过编辑器可维护的 `story_art_library.tres` 白名单显式引用，JSON 只给 art_key。
  新故事只增加 JSON、本地化及必要美术映射，不改 UI、路由或应用代码。
- bootstrap 是唯一组装入口，注册 story_archive 路由；主菜单只改变开始/返回的导航动画。
- 不加入天气、音频、角色创建、存档或实际剧情。用户第五/六节明确说不需要天气和声音，
  后续将决策交给开发方时采用这一收敛范围；图中的雨是静态插画的一部分。

## 生命周期与兼容

新端口没有旧消费者，不修改 A1 对话/探索/模型协议或状态快照格式。
UI 在转换期间锁定提交；预览使用递增修订号和可取消 Tween，退出立即销毁动画。
返回 main 菜单不重播长开场。测试替身仅存在 tests/story_archive。
未来若启动变成异步协议，必须另行定义请求 ID、取消、终止和状态原子性，不能将当前
同步 Result 偷换为“已启动后台任务”的假成功。
