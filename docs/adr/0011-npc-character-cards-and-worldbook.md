# ADR 0011：NPC 角色卡与世界书的接入方式

日期：2026-10-03。状态：已实施（本机验证，未推送）。工作包：NPC 角色卡 + 世界书接入。
依据 PRD §5.1、§9、§10.2、§10.3、§14.2、§17.4；用户交付角色卡（艾米利亚与玛丽）与世界书整理版，
并要求把两个角色接进书房与接待室 NPC。

## 背景

在此之前，庄园的两个 NPC 是明确标注“身份待确认”的合成预览：说话人档案只有本地化名牌和空立绘 ID，
知识目录是空数组，系统提示词是单份固定文本。上一轮已确认这三点是缺口（无人物卡、无世界书）。

用户随后提供了两份正式来源：一份 AI 接入版角色卡（含人格提示词、状态机、知识白名单、禁用句、兜底台词）
和一份世界书（13 节，显式区分公开/调查/隐藏/运行四层）。

## 决定

1. **角色卡成为受校验数据**：`data/ai/npc_characters.zh_CN.json` + 严格 Schema + `CharacterCard` 领域校验器。
   说话人不再是“名牌 + 空立绘”，而是绑定到一张角色卡：人格模板、状态枚举与初值、信任/恐惧上限、
   禁用句、气泡预算、立绘 ID。人格模板里的每个 `{占位符}` 必须有对应初值，否则构造期就失败。
2. **世界书成为分层数据**：`data/ai/deadlight_worldbook.zh_CN.json`。条目保留来源文档的可见性分层，
   并显式声明受众（`speakers` 或 `public_scene`）。派生 F1 fact 时取“受众 ∩ 本场景说话人”，
   每条条目只产出一条 fact（避免同一事实因多受众而重复）。
3. **隐藏层安全不变量**：`hidden` / `running` 层禁止携带 NPC 受众，校验器拒绝，测试固化。
   真相层因此只能留给未来的 AI 主持人（`WorldBook.narrator_entries`），不可能被误接给 NPC。
4. **知识隔离沿用 F1**：NPC 只拿自己的白名单事实；玛丽的抢劫真相与死光真相不在她的可信事实里。
   她的“知道但不承认”由人格模板 + 禁用句校验表达，而不是把真相塞进事实目录。
5. **输出硬校验按角色配置**：`ReplyValidator` 接受可选的角色输出策略（禁元层暴露、角色禁用句、气泡预算）。
   策略在结构、说话人、事实与动作校验之后运行，拒绝按可重试失败处理。
6. **站位映射**：艾米利亚→韦伯医生书房，玛丽→庄园接待室。玛丽的本章初始岗位是加油站，
   接待室是她潜入销毁证据的场景 B 站位；这条差异在 `docs/npc-characters.md` 显式记录。

## 兼容性

- `DialogueConfiguration` 只新增一个**可选**键 `reply_policies`；`speakers` 的形状（name_key、portrait_id）
  未变，既有 F1/G1/I1 消费者与夹具不受影响（不传 `reply_policies` 时行为与之前一致）。
- `ChatCompletionRequestBuilder.create` 新增可选的第三参数 `personas`；不传时不注入人格，
  既有调用点（含测试）行为不变。占位符校验在构造期完成，避免请求期才发现缺文本。
- `ReplyValidator.validate` 与 `ManorNpcAi.begin` 增加了可选参数，旧的调用方式仍合法。
- 场景 ID 固定为 `manor`（动作契约仍绑定它），房间通过**话题 ID**（`manor.room.<room>`）参与知识过滤，
  因此房间维度不触碰动作契约。
- 说话人 ID 由 `preview_reception` / `preview_study` 改为 `mary` / `emilia`（F1 要求小写 ID）。
  本地化键、测试与截图脚本同步更新；`preview_*` 只作为历史记录留在旧 ADR 与接续记录里。
- 归档的合成夹具（F1/G1/I1 测试里的 `preview_actor` 等）保持原样，不受影响。

## 后果与限制

- 角色卡里的运行时机制（信任/恐惧增减、逆鳞强制结束对话与沉默、失谐波纹 UI、行为树、检定）
  **本轮没有实现**，初值只是初值；`taboo_triggers` 与 `gate_flags` 作为数据与状态占位保留。
- 输出校验是字符串启发式，不是语义证明；误拒表现为可重试失败，误放行仍可能发生。
- 玛丽的提示词按角色卡包含“她做过什么”的真相（否则无法演出“回避而非撒谎”），
  风险由“事实目录不含真相 + 禁用句校验 + 未实现坦白门”共同承担；这是角色卡的设计意图，不是泄漏。
- 立绘资源不存在；`portrait_id` 已就位，视图显示占位提示。
- 正式《死光》检定公式、缺失对话节点、开场动画与加油站场景仍待授权正文与后续工作包。

## 验证

架构检查 202 个源/场景文件 + 3 项负向用例通过；等价三步验证（架构、导入、聚合测试与启动标记）
`AIRPG_TESTS: 1049 checks, 0 failures`，其中 NPC_AI 94 项覆盖角色卡 Schema 与领域校验、
世界书分层与受众、narrator 层安全不变量、跨 NPC 知识隔离、披露门开合、房间碎片过滤、
禁用句与允许句、气泡预算、人格渲染、以及端到端“禁用句回复不进入视图”。未使用真实 API Key。
