# AIRPG 架构基线

状态：已实现骨架。依据：PRD v0.1 第 16–18、21 章。日期：2026-09-26。
本文件中的后续设计不是已完成功能；不更改 PRD 中仍待确认的产品决策。

## 1. 组织方式

采用模块化单体。发布物是一个 Godot 客户端，内部按业务边界和依赖方向隔离。
按“层 / 领域”组织；功能增长时在对应层建立 `exploration`、`dialogue`、`rules` 等子目录。
不提前建设微服务、通用插件执行器、ECS 或全量事件溯源框架。

| 目录（相对 game） | 职责 | 允许依赖 |
| --- | --- | --- |
| `shared` | Result、纯数据结构校验 | shared |
| `domain/content` | 内容定义与引用完整性 | domain、shared |
| `domain/story` | 条件、不变量、权威状态 | domain、shared |
| `application` | 面向 UI 的用例、编排、外部端口 | application、domain、shared |
| `infrastructure` | 文件、输入、翻译、随机源、模型与存储适配器 | infrastructure、application、domain、shared |
| `presentation` | 场景、UI、动画、路由 | presentation、application、shared |
| `bootstrap` | 生命周期、依赖组装、启动检查 | 所有生产层 |
| `data` | 配置、本地化、内容及版本化 Schema | 无代码依赖 |
| `tests` | 行为与集成验证 | 所有层 |

只允许 `bootstrap` 把具体适配器与应用用例装配到一起。UI 接收构造完成的用例，不自己找全局服务。
同层也不意味着共享所有内部对象：跨领域交互经公开用例或端口；禁止依赖循环。
基础检查扫描 `.gd/.tscn/.tres` 的资源依赖、禁止的 I/O 与动态全局入口；它是回归检查，不是完整语义证明或安全沙箱。

## 2. 启动、生命周期与呈现

`main.tscn` → `main.gd` 加载界面翻译 → `Composition.build` 验证配置和内容 → 创建独立状态与会话 → 注册输入 → 打开主页。
`Composition` 不操作场景树，允许无界面测试。每次构建创建新会话，不借用上次游玩的状态。
`SceneRouter` 只管理传入的场景宿主，切换前验证目标；无效路由保留旧视图。
会话活得比场景长，场景释放不会销毁会话。未来退出游戏/读档重建会话时，由启动层取消请求和释放资源。

UI 使用容器、锚点和 1920×1080 缩放基准。键位在 JSON 中映射到动作，探索模块消费动作而非直接写死 W/A/S/D。
以后增加触控适配器时保留动作名称，不让移动规则依赖键盘事件。当前只实现动作注册，没有移动角色。

调试面板仅在开发构建且配置启用时开放，接收明确列出的诊断字段。
完整开发者面板未来经专用只读诊断接口扩展；不要把整个模型客户端或状态对象绑定给 UI。

## 3. 状态权威与一致性

内容定义是静态数据，会话状态是动态数据，渲染状态属于 UI，三者独立。
当前状态仅包含版本号与预声明的布尔标记。`StateStore.commit(expected_revision, changes)` 完整验证后一次替换状态，并增加版本号。
所有输入/输出快照深拷贝；领域层以 `_` 字段约定隐藏可写对象。GDScript 没有强私有边界，仍需代码复核。
应用层未来只暴露有业务含义的命令；UI 不拥有通用 `set_flag` 权限，模型更不能获得此权限。

后续每个用例应遵守：

1. 记录会话 ID、请求 ID、预期状态版本；读取快照。
2. 依据内容和规则计算候选结果，暂存物品变化、骰点、关系、剧情推进。
3. 完成所有格式、权限、事实边界和状态校验。
4. 检查请求仍有效且会话版本未变化，再一起提交。
5. 提交后发送类型明确的领域事件，日志与 UI 订阅该事件。

任何一步失败都不得提交部分结果。固定随机数也必须纳入事务：从检查点创建试算随机源，提交时一起保存其新状态。
当前只实现布尔标记的原子提交与独立随机检查点，不声称已完成多资源事务、检定或完整存档恢复。
会话状态由 Godot 主线程拥有。网络/后台任务将结果投递回主线程，不直接并发修改状态。
并行开发指独立任务与分支，不能据此把业务状态改为多线程共享可写对象。

## 4. AI 信任边界

AI 供应商替换发生在 `ModelProvider` 端口背后。供应商不做剧情提交、检定结算或知识选择。
模型名、URL、上下文预算、参数从外部配置进入适配器；密钥只由适配器读取，绝不进入端口响应、诊断或内容资源。
现有默认适配器明确返回 `AI_NOT_CONFIGURED`，不会伪装联网或生成保底剧情。

后续对话用例必须分开：

- 知识选择：按 NPC 身份、已允许事实、公开现场、来源明确的记忆筛选。NPC 上下文无完整模组。
- 请求组装：权威事实与不可信玩家输入/笔记/历史陈述分字段，不升级其权限。
- 传输：处理 SSE 分片、UTF-8 边界、超时、取消、请求标识、终止信号与用量。
- 校验：结构与允许动作验证、事实和透露条件验证、语义一致性复核。
- 发布：仅将验证过的内容交给 UI；提交状态与显示输出由同一用例控制。

PRD 同时要求流式体验与“校验通过后显示”。骨架只冻结安全边界：原始 delta 不得直接连接 UI。
首个 AI 工作包需明确“整条缓存校验后渐进显示”或“独立可校验片段流”，并交由产品确认等待体验；不能把原始 token 提前展示后再撤回当作知识隔离。
JSON Schema、事实 ID 白名单不能证明自然语言没有新增事实。真正语义保证仍是 AI 阶段的高风险验收项，不能靠提示词或二次模型评分宣称彻底解决。

## 5. 数据、兼容与存档

Schema 是版本化契约，不是任意字典接口。当前 v1 只定义内容目录信封、引用、本地化和布尔前置条件。
完整角色、规则、剧情效果、NPC 知识字段会由对应工作包补充专用 Schema，不增加无约束的 `payload` 逃生口。
内容加载前检查大小/JSON 格式，之后结构校验，再检查重复 ID、引用、本地化和条件引用。失败阻止启动。
运行时校验器只支持文档列出的 Schema 子集；不进行远程 Schema 获取，不执行表达式。

持久化端口只负责读写快照。正式实现需要 schema_version、content_version、engine_version、会话状态、随机状态以及事务边界。
写盘应使用临时文件与替换策略，验证失败不能覆盖原存档；版本迁移是显式纯函数，并有旧版样本测试。
旧版本不认识的新格式必须报错，不能默默丢弃字段。内容升级导致 ID 变化时需要迁移映射。
当前 `MemorySaveRepository` 只服务于测试；还没有磁盘存档、手动保存策略、历史记录和迁移器。

随机源保存 seed + state 的十进制字符串，避免 JSON 浮点数损失 64 位精度。算法与引擎版本锁定；不承诺跨引擎版本的随机序列一致。

## 6. 日志与异常

接口用 Result 返回稳定错误代码，禁止把供应商原始错误或含请求头的异常直接展示/记录。
现有日志只输出启动代码和测试汇总，完整会话日志尚未实现。
后续日志模块按明确字段白名单记录事件，并对结构化字段与自由文本同时脱敏；禁止仅按 `api_key` 字段名替换就声称安全。
AI 原始输入/输出仅在受控开发诊断通路可见，带大小限制、敏感值移除及玩家隐私策略。
日志包含 trace/request ID、耗时、token 与成本计价版本；未知成本标记未知，不能填写 0 伪装免费。

## 7. 规模增长时的约束

- 新功能先定义最小跨模块契约和失败语义，再写适配器。仅为实际替换点建端口。
- 每个领域拥有自己的状态切片和验证器，由应用事务协调，不新建万能 GameManager。
- 对高频移动和渲染使用本地节点状态；不把每帧位置写进剧情事件总线。
- 只在测量确认瓶颈后引入后台处理、缓存或分块加载。性能预算尚待产品确认。
- `shared`、`bootstrap`、契约与 Schema 由架构负责人审阅；功能负责人不能独自放宽边界。
- 改引擎、依赖图、存档/内容格式或 AI 发布策略，需更新 ADR 和受影响测试。
- 当前脚本 300 行上限是拆分提醒，不是拆成无意义小类的理由。
