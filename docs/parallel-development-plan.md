# AIRPG 并行开发计划（阶段 B 启动版）

状态：待派工。依据：PRD v0.1、`docs/architecture.md`、`docs/contracts.md`、`docs/workstreams.md`。  
目标：在不提前写死检定公式、正式剧情和 NPC 知识的前提下，把当前工程骨架推进到可操作、可展示、可对抗验证的灰盒基础。

## 当前判断

- 现有架构基线可用：本机固定 Godot 4.7.2 下，架构检查、3 项负向检查、导入、63 项行为/集成检查和真实启动均通过。
- 仓库尚无首次提交，全部骨架文件仍未跟踪；在建立唯一基线提交前，不能安全创建标准 Git worktree。
- `bootstrap`、公共端口、全局 Schema、本地化、测试总入口属于共享冲突区，只允许架构/集成负责人或独立契约 PR 修改。
- 这一轮不导入正式《死光》内容，不确定检定公式，不实现磁盘存档，也不把测试数据描述为正式玩法。

## 波次 0：并行前串行门槛

负责人：A 架构 / 集成。其他功能开发暂不改共享文件。

### 0.1 建立 Git 基线

1. 确认工作区内容全部属于当前 AIRPG 骨架。
2. 运行统一验证并记录结果。
3. 建立唯一首次提交；所有后续分支和 worktree 从该提交创建。

### 0.2 A1 最小契约冻结

只冻结当前并行包必需的接缝，不加入正式故事数据。

- 探索：动作命令、互动候选、互动请求、探查请求、稳定错误码。
- 对话 UI：请求 ID、展示状态、说话者/立绘资源 ID、推荐选项、已验证文本、可重试错误。
- 模型传输：接受/取消/完成/失败生命周期、一次终止语义、超时与取消错误码。
- 发布策略：第一阶段采用“完整缓存 → 完整校验 → UI 渐进播放”；原始 `raw_delta` 永不进入玩家 UI。
- 测试替身：探索用例替身、对话用例替身、可编程模型 Provider 和合成夹具的位置与接口。

### 0.3 J0 测试入口整理

- `game/tests/run_tests.gd` 继续作为唯一聚合入口，由集成负责人维护。
- 新功能分支只新增自己目录内的独立测试文件和夹具，不并发修改聚合入口。
- 现有基础测试可后续拆套件，但不能用空测试文件伪装覆盖。

门槛验收：统一 Verify 全绿；契约测试通过；消费者清单、稳定错误码和目录所有权已记录。

## 波次 1：三条实现线并行

每个工作包使用独立负责人、分支、worktree 和 PR。负责人目前均标记为待分配。

| 工作包 | 建议分支 | 独占目录 | 交付范围 | 明确非目标 |
| --- | --- | --- | --- | --- |
| C1 灰盒探索 | `feature/c1-exploration` | `game/presentation/exploration`、`game/application/exploration`；经评审扩展 `game/infrastructure/input` | WASD 移动、碰撞、预设互动范围、互动请求、探查冷却和合成灰盒场景 | 不算骰、不直改剧情、不加入正式线索、不支持任意物体自然语言调查 |
| I1 对话呈现 | `feature/i1-dialogue-ui` | `game/presentation/dialogue` | 传统 RPG 对话框、推荐选项、自由输入原样提交、历史、等待/暂停/错误/重试、验证后渐进显示 | 不访问模型、不选择 NPC 知识、不提交剧情状态、不显示原始流 |
| G1 模型传输 | `feature/g1-model-transport` | `game/infrastructure/ai` | 供应商无关配置接缝、DeepSeek SSE 解析、UTF-8 分片、超时、取消、一次终止、用量与错误脱敏；使用离线录制夹具 | 不选择知识、不做语义裁决、不结算规则、不写状态、不要求真实 API 密钥 |

### C1 验收

- WASD 通过动作名而非硬编码键位移动，碰撞有效。
- 进入/离开范围、隔墙、长按和重复触发均有明确行为。
- 文本输入获得焦点时，移动、互动和探查不会误触。
- 探查有冷却、场景内不限次数；本包只返回合成结果。
- 场景退出后不留下仍能修改界面的回调或节点引用。

### I1 验收

- 推荐选项与自由输入同时可用，玩家输入不经 AI 润色。
- 等待、失败、取消和重试状态可理解，历史记录只读。
- 只消费应用层发布的“已验证文本”；原始模型分片不可连接 UI。
- 长文本、缺失立绘、缺失本地化和不同 16:9 分辨率不阻断操作。
- UI 仅持有应用用例/展示状态，不持有 StateStore、网络或存档句柄。

### G1 验收

- 覆盖 UTF-8 字符跨分片、JSON 跨分片、CRLF、心跳、半截数据、断流和 `[DONE]`。
- 每个被接受请求恰有一个终止信号；取消幂等，迟到和重复终止被拒绝。
- 超时、HTTP 错误、响应过大和供应商异常转换为稳定错误码。
- 密钥、请求头和供应商原始敏感错误不进入日志、诊断或返回值。
- 离线契约测试通过不等于真实 DeepSeek 联调完成；真实调用留到后续独立验收。

## 与波次 1 同步的独立对抗线

负责人：J QA / 对抗，必须与功能实现者不同。QA 不直接修业务代码，只提交失败证据、最小复现和独立测试。

建议基于各功能分支建立堆叠分支：

- `qa/c1-adversarial`：隔墙互动、范围边界、输入焦点、重复触发、探查冷却、场景释放。
- `qa/i1-adversarial`：原始流泄漏、连续提交、切场景后迟到回复、取消、重试、长文本与分辨率。
- `qa/g1-adversarial`：乱序/断流/双终止、错误 request ID、取消后回调、UTF-8 分片、脱敏和响应大小。

QA 仅写 `game/tests/<work-package>/` 和对应合成夹具。测试总入口仍由集成负责人单点登记，避免冲突。

## 波次 2：单点集成

负责人：A 架构 / 集成，建议分支 `integration/slice-wiring`。

1. 按 G1 → C1 → I1 的顺序吸收工作包；实际顺序可按依赖调整。
2. 统一修改 Composition、主场景、路由、配置、本地化和测试聚合入口。
3. 运行全量 Verify 和 J-INT 联合故障注入。
4. 对抗负责人出具独立结论；未解决的阻断问题不得以“后续优化”跳过。

集成验收：请求失败不推进状态、不消耗物品、不提交骰点；过期/取消回调不能显示；场景释放后会话生命周期正确；固定随机种子仍可复现；架构负向检查继续有效。

## 暂不启动的工作包

- D1 检定内核：等待切片使用的精确公式和预设角色数据确认。
- B1 正式内容格式与 B2《死光》内容导入：等待授权正文的结构化输入和具体开场内容确认。
- F1 知识与对话边界：等待 NPC 知识、话题和事实格式契约完成会审；不得只靠提示词宣称防泄漏。
- H1 磁盘存档与完整日志：等待完整会话快照、保存资格和版本迁移契约。
- 美术正式接入：可并行制作风格基准、角色参考和灰盒替换清单，但不要在本轮同时修改功能分支的 `.tscn`；由集成波次统一替换资源。

## 每包完成定义

- 只修改声明的目录；共享文件变更另开契约/集成 PR。
- 正常、失败、边界或竞态路径均有测试。
- `scripts/verify.ps1` 全通过，不能只看 Godot 退出码。
- 新 `.gd` 同时提交 `.gd.uid`。
- 固定文本本地化；无密钥、授权正文或敏感原始响应进入 Git/日志。
- PR 说明范围、非目标、依赖基线、验证结果、未验证的真实环境和对抗复核重点。
- 修改契约、状态格式、Schema 或 AI 发布策略时，同步 ADR、消费者、兼容说明与回归测试。
