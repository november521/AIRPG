# 岗位与并行工作包

## 所有权

当前架构负责人为本任务；其余岗位待用户安排员工或独立开发任务。这里定义角色与交付边界，不虚构已经在工作的人员。
一位员工可在不同时期承担多个岗位；每个工作包只能有一个明确负责人。对抗复核应由实现者之外的人员完成。

| 岗位 | 主责目录（相对 game） | 负责交付 | 不得越界 | 必要验收 |
| --- | --- | --- | --- | --- |
| A 架构 / 集成 | bootstrap、shared、docs、scripts、.github | 依赖图、契约、装配、版本、CI | 不替产品确定剧情和规则 | 全项目检查、契约消费者一起升级 |
| B 内容 / 数据 | data/packs、data/schemas、domain/content | ID、专用 Schema、引用与授权内容映射 | 不写任意执行脚本、不能从公开简介补编秘密 | 坏数据、缺失本地化、角色权限夹具 |
| C 探索 / 场景 | presentation/exploration、application/exploration、infrastructure/input | 移动、碰撞、预设互动、探查呈现 | 不自己算骰点，不直改剧情状态 | 交互范围、重复操作、输入焦点、场景退出 |
| D 规则 / 检定 | domain/rules、application/rules、infrastructure/random | 规则结算、检定明细、候选结果 | 不调用模型，不依赖场景树 | 边界概率、固定种子、失败回滚 |
| E 剧情 / 状态 | domain/story、application/story、application/session_service.gd | 用例命令、状态事务、事件、笔记事实区分 | 不按 AI 指示任意改状态 | 过期/重复提交、原子性、状态不变量 |
| F 对话 / 知识 | domain/dialogue、application/dialogue | 话题权限、上下文投影、响应校验与发布 | 不发送完整模组，不泄露未经验证流 | 越权询问、秘密泄漏、假事实、迟到回调 |
| G 模型 / 传输 | infrastructure/ai、application/ports/model_provider.gd（契约会审） | DeepSeek 适配、SSE、超时、取消、用量 | 不结算规则，不选择 NPC 知识、不写状态 | 分片/断流/终止、取消/重试、错误脱敏 |
| H 存档 / 日志 | infrastructure/persistence、infrastructure/telemetry、application/persistence | 原子写盘、迁移、会话日志、复现 | 不绕过用例检查保存资格 | 损坏文件、版本、断写、敏感值、RNG 恢复 |
| I UI / 美术声音接入 | presentation/shell、presentation/dialogue、presentation/debug、assets | 自适应 UI、记录页、立绘声音表现 | 不嵌入业务规则或写死台词 | 分辨率、键鼠焦点、等待/错误体验 |
| J QA / 对抗 | tests、docs/testing.md | 契约测试、集成复核、风险回归 | 不替功能负责人偷偷改业务实现 | 测试可独立复现，失败证据明确 |

未出现的目录在对应工作包开工时创建，不用空类/空目录伪装已实现能力。
bootstrap、shared、全局 Schema、输入动作名称、公共端口由 A 审查后变更。
同一领域的应用/领域代码归同一个工作包负责人，不把一个功能拆成“前端完成但等后端”式无人整合交付。

## 分支与整合协议

每个工作包一条 `feature/<work-package>` 分支、一个独立 checkout/worktree；不得共用工作目录并发写文件。
首次提交建立之前无法创建标准 Git worktree；先由集成岗位建立仓库基线，再分发并行分支。
每个任务开工须写明：PRD 条目、范围/非目标、目录所有权、输入输出、依赖基线、验收和复核人。
公共契约变更走独立小 PR，消费者在契约合并后并行工作；不要靠每天同时改 `main.gd` 解决依赖。
集成只接受“代码 + 失败路径测试 + 接入说明”的完整工作包。所有 PR 必须过 Verify / foundation，并经相关所有者复核。
当前尚未设置 GitHub 规则集/强制检查或真实 CODEOWNERS；需要确定人员账号并首次推送后才能实际启用。

| 包 | 负责人 | 前置依赖 | 边界与验收 |
| --- | --- | --- | --- |
| A1 契约细化 | A + B + E | 本骨架 | 专用场景/状态/互动 DTO，错误码与接口假实现；通过契约测试 |
| C1 灰盒移动互动 | C | A1 场景/互动契约 | 纯合成灰盒、WASD、碰撞、预设互动；无正式线索与自由环境输入 |
| D1 检定内核 | D | 公式与角色属性产品确认 | 概率/掷骰/候选结果；原子提交与固定种子测试 |
| I1 对话呈现 | I | F1 的展示/等待/错误事件契约 | 推荐选项、原样输入、已验证文本渐进显示；使用测试替身 |
| F1 对话边界 | F | B 的知识/话题格式、流式发布策略确认 | NPC 上下文隔离、状态提案验证、失败暂停；无真实 API 也可测 |
| G1 DeepSeek 适配 | G | provider 配置与传输 DTO 契约 | 实现传输端口；先离线分片测试，后经授权真实调用 |
| H1 存档日志 | H | E 的会话快照与保存资格契约 | 原子磁盘写入、脱敏日志、随机状态恢复；损坏/中断夹具 |
| J1 对抗套件 | J | 随各契约持续补齐 | 关注输入越界、回调竞态、伪事实、断流、存档破坏 |

A1 结束后，C1、已冻结契约的 I1/G1 和 J1 可以并行。D1/F1/H1 取决于各自业务决策，不能为了并行进度先写死假规则。
没有授权正文时，仅可使用明确标注且不进入正式内容包的合成测试数据。

## 每包交付模板

任务名 / 负责人 / 复核人 / PRD 条目 / 目录所有权 / 依赖提交 / 范围 / 非目标 / 契约 / 测试命令 / 验收结果 / 已知限制 / 对抗风险。
交付后由 A 完成装配与全局回归，J 记录对抗结论，再进入下一包。
