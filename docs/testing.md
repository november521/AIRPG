# 骨架验收与对抗检查

## 可复现入口

PowerShell 7：`./scripts/verify.ps1`，或 `-Godot <固定版本引擎>`。
不需要网络、API 密钥、MCP 或第三方测试库。
首次安装引擎才需要网络：`./scripts/install_engine.ps1`。

验证脚本检查精确引擎版本，并依次运行：

1. 生产资源依赖方向、缺失脚本/场景、循环、越层 I/O、全局入口与脚本长度检查。
2. 3 个架构负向用例：反向依赖、依赖循环、UI 直接写文件必须被拒绝。
3. Godot 无界面导入。
4. GDScript 行为/集成测试。
5. 真实主场景无界面启动，检查 AIRPG_BOOT_READY 标记。

引擎退出码为 0 仍可能记录脚本错误，所以脚本同时检查 ERROR/SCRIPT ERROR 和完成标记。
每次运行覆盖 `artifacts/import.log`、`tests.log`、`boot.log` 及对应 engine.log。
不要将退出码为 0 或只有编辑器能打开，当作所有功能测试通过。

## 当前覆盖

| 边界 | 已检查行为 |
| --- | --- |
| 内容 | 正常目录、重复 ID、缺失引用/本地化、未知标记、类型错误、未知字段/版本、畸形条目、空值、JSON 整数解析 |
| Schema | 不支持关键字拒绝，包括数据中未出现的可选属性的 Schema；结构校验先于语义校验 |
| 状态 | 初始化失败/重复初始化、输入输出隔离、混合非法更新不部分提交、版本递增、迟到结果拒绝 |
| 条件 | 空合取、已声明布尔条件、缺失键与未知操作拒绝 |
| 随机 | 同种子 32 次一致、JSON 检查点后续 16 次一致、非法骰子/算法/64 位溢出不改变序列 |
| 端口 | 基类与未配置模型明确失败、内存存档读写隔离 |
| 启动 | 真实配置与空内容包装配成功、缺失配置失败、输入注册与非法绑定原子拒绝 |
| 场景 | 主场景启动、来回切换只有一个活动视图、未知路由保留原场景 |

CI 使用 GitHub Actions 的普通 `pull_request` / `push main` 事件、只读 contents 权限和不持久保存凭据的 checkout。
工作流依据 [GitHub Actions 官方语法](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax) 配置，并经 github-actions-docs 技能核对；与本地调用同一验证脚本。
引擎归档锁定 SHA-256，下载后校验版本。该哈希来自当前官方引擎归档基线并已重新下载比对；不是代码签名或独立发行方证明。

## 骨架验收与切片验收的区别

本轮验证只证明骨架接缝与基础组件的行为。PRD 第 20 章的 10 局 AI 无泄漏、10–15 分钟通关、3–5 人试玩、成本日志、完整存档均未执行，也不能在此阶段宣称通过。
未做 Windows 图形窗口人工验收、不同 DPI/分辨率完整视觉验收、打包导出或性能测试。
GitHub 云端运行和分支强制检查需要首次推送后验证；本轮在本机运行了同一安装与验证流程。

## 对抗复核重点

- 检查 UI / 网络适配器是否获得可写 StateStore；领域字段的下划线不构成语言级访问控制。
- 静态扫描可识别直接路径与常见 I/O，不识别一切反射和间接调用。不要把它当成不可信脚本沙箱。
- 内容目录当前没有完整 NPC 知识/技能/剧情效果字段；不得把 metadata 校验当作事实授权。
- 未来 raw_delta 到 UI 的任何连线都是高风险变更；对话取消和重试须防迟到/重复提交。
- 当前布尔原子提交不包含 RNG、物品与日志事务，检定实现时必须补齐联合失败回滚。
- 内存存档不是持久化；磁盘原子替换、版本迁移、坏文件、长整数字段与恢复中断需要专门测试。
- 模型提示词不能证明无幻觉；语义事实校验与真实模型对抗集仍是首个 AI 包的必要交付。
- 玩家文本、授权内容和 API 响应的日志脱敏尚未实现；在引入这些日志前先实现白名单与文本脱敏。

每项风险应由对应功能包添加回归样本，避免只有检查清单而没有可执行证据。
